## Rulings and tradeoffs

- Lost pointer capture cancels rather than feeding, preventing accidental consumption; a drop may need retrying.
- Work areas narrower than two 300px zones plus the 48px jar skip placement, matching the explicit plan test; narrow displays may not show jars.
- Prop lint uses native square dimensions and checks every edge; treat images remain outside outfit metadata. This keeps outfit loading independent of treats; future nonsquare props need another lint rule.
- Drop targets use the centered bottom 96px sprite with the 12px inset, rather than speech-bubble-expanded bounds; empty space cannot feed him, but aim is stricter.
- Any keyboard input cancels a held treat, including Alt-Tab. A 30-second watchdog bounds recovery if release paths fail; typing or a very long intentional drag requires retrying.
- Window lifecycle and reaction sequencing are extracted into small modules for meaningful tests using injected Electron boundaries; this adds two internal modules without changing the approved feature scope.
- Windows imposed a 39px native minimum window height for a 32px treat on this PC. Art/canvas remain 32px; unused pixels are transparent. No OS workaround was shipped.
- Physical input/hardware checks remain explicitly unverified, with simulated tests used only for the code paths they exercise. Residual native capture behavior requires a hands-on check.
